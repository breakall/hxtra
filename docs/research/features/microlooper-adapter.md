# Atmosphere-looper native stereo adapter investigation

2026-11-14. Stock HX Stomp 3.80.0 MD5 `a2cd8f4ae56f49415380270ebc484bf1`, SHA-256 `a56d2be006e7ecb5bbaf93ca0d7759653b654871720f330c232bfe1f2b3fdbfc`. No hardware operations or firmware writes were performed. Scope: establish what is known about the stereo call interface, and prepare a diagnostic without pretending that a synthetic simulator interface is the native one.

Current development initialization, allocation dataflow and complete build integration are recorded in [microlooper-integration.md](microlooper-integration.md). The investigation below retains the distinction between offline native-code evidence and physical stereo/loader qualification.

## Findings and correction to earlier graph interpretation

**[verified offline: stock metadata parsing]** The regular stereo host `L6SPB_AcousGtrSimStereo`, blob 469/composite `0x600096`, has **root 0-in/2-out**, not 2-in/2-out. Member 1 is the 2-in/2-out primitive `0x9c51`, in place on buffer numbers `[0,1]`. Its source registry descriptor is at normal-word `0x200580`; process entry `0x8e9e3`, instance DM 129 words, PM 0 words. The [inspection tool](../../../tools/sharc/microlooper_adapter.py) reproduces these observations directly from the caller's `.hxf`. The graph root's input-port count does not describe physical sample pointers.

**[verified offline: stock metadata parsing]** The One Switch Stereo Looper also has root 0-in/2-out, with a2-in/2-out member 1 primitive `0x271f`. Thus root port count is **not** evidence that the looper uses a uniquely specialized calling interface. Actual structural differences: the regular host has 3 members and no extra audio buffers; One Switch Stereo has 5 members, 1 extra audio buffer and two mono gain stages; `HD2_AppLooperHarness` has 10 members and 6 outputs with additional nested routing. These differences justify investigating looper transport/routing separately, but do not establish that reusing its core would be harder than using an ordinary effect. Sources: [graph parser](../../../tools/sharc/entry4_blob.py), [FX host construction](../../../tools/kit_patch_amp.py), stock image above. No Line 6 code is reproduced here.

**[verified on unit: existing recorded evidence]** The compressor research records a two-input primitive with `I1` circular length32 and `I2` length16. That is consistent with two 16-sample regions in an input buffer; it does not prove which layout the selected stereo primitive receives. Read [compressor buffer research](../sharc/cores/compressors.md) and [primitive/control conventions](../sharc/registry.md). Do not extrapolate a mono primitive's `I1=input,I2=output` convention into interleaved stereo without an observed native call.

**[verified offline / limitation]** The REA tool schemas available in this session do not advertise a SHARC raw-binary architecture. Its firmware-region scanner requires a Linux host, while this workspace is macOS. No provider/tool installation was attempted. The additional bounded replay below establishes the ISA bridge's register dataflow, but does not execute its VISA body or prove audio lane order.

**[verified offline / historical-source limitation]** An earlier local HD500 research project analyzes HD500-era firmware with a different L6IA layout and six-word selector descriptors. Its host runner uses lower/upper 16-word lanes as an explicit host convention; neither those addresses nor that channel convention establish HX Stomp behavior. It is not used as native ABI evidence here.

## Reproducible ISA-to-C bridge dataflow

**[verified offline: real encoded instructions, synthetic caller]** `trace_process_bridge` in the inspection tool loads the supplied image's INIT48 instructions and INIT32 data into the existing `ssim`. It runs at most256 instructions and stops before entering an INIT16 code region. It does not skip unsupported instructions. Its report contains addresses and resulting argument registers, never firmware instructions or payload bytes. The synthetic addresses deliberately distinguish input, output and instance pointers.

The stock path executes55 ISA instructions:

| Location | Established dataflow |
| --- | --- |
| `0x8e9e3` | Calls bridge `0x8cbf6`. |
| `0x8cbf6..0x8cbf8` | Copies incoming `I1` to `R4`, `I2` to `R8`, and `DM(2,I3)` to `R12`. |
| `0x8c79f..0x8c7c2` | Shared C environment setup resets index registers; the three argument values survive. |
| `0x8e9e4` | `CJUMP` targets `0x17ad40`; two delayed instructions run before the target. |
| `0x17ad40` | Target is contained in INIT16 block `[0x17973b,0x17bffb)`, count10432 short words. |

The **only data read** during this bounded stock path is `DM(2,I3)`. Therefore it proves where the existing instance pointer is passed to C, but does not tell whether `I1` and `I2` name float arrays, pointer arrays or another structure. In particular, the bridge never reads an audio sample. SDRAM words6/7 remain prior NAM evidence; this path does not dereference them.

**[verified primary documentation]** The ADI [ADSP-21469 memory map](https://www.analog.com/media/en/technical-documentation/data-sheets/ADSP-21467_21469.pdf) places `0x17ad40` in block1 short-word SRAM. The [SHARC Programming Reference](https://www.analog.com/media/en/dsp-documentation/processor-manuals/ADSP-2136x_2137x_214xx_pgr_rev2.4.pdf), sections4-5/4-18 and chapter10, establishes address-selected VISA execution and the16/32/48-bit forms. Thus the earlier replay stop is **a missing VISA fetch/decode path, not missing firmware bytes**. Existing `ssim` fetches one48-bit instruction per normal-word PC and cannot enter this body correctly.

## Conditional VISA buffer geometry and initializer

**[verified offline under explicit parcel-order assumptions]** [microlooper_visa.py](../../../tools/sharc/microlooper_visa.py) now decodes only the required forms. The caller must select INIT16 parcel order; external VISA order is selected separately when needed. Unsupported compact forms stop inspection, including unresolved compact dual-memory/modify forms. Negative immediate16 extension remains unsupported by default; the bounded float-use experiment explicitly compares both extension hypotheses. No normal-word/short-word alias rules or VISA changes were added to shared `ssim`. Tests independently check translated forms against our assembler and check mixed-width delayed jumps and DO-loop start/repetition metadata. This is a bounded inspection helper, not a general emulator.

Under **INIT16 high-half-first**, the original path at `0x17ad40` follows the instance descriptor's word0 to private DM, places incoming I1/I2 into private fields3/4 and enters `0x13adb4`. Its first input-copy loop reads words at the following addresses; the bounded consumer proof below establishes their float use under the same order assumption:

`incoming I1 + j * private_DM[0] + k`

Here `j` is R13, initially zero, and `0 <= k < private_DM[0]`. The decoded input load uses unit modifier M6 and copies each word to the pointer in private field122. Static outer-loop checks establish `j` increments until it reaches private field2. The output row base uses `incoming I2 + j * private_DM[0]`.

| Address | Checked operation or role |
| --- | --- |
| `0x13ae1d` | Clears row index R13. |
| `0x13ae58`, `0x13b125` | Input/output row-width read from private field0. |
| `0x13ae5d`, `0x13ae60` | Input pointer field3 plus integer product R13 × row width. |
| `0x13ae67..0x13ae6d` | Counted, unit-stride input-word copy into staging memory. |
| `0x13b126`, `0x13b129` | Output pointer field4 plus the same row product. |
| `0x13b147..0x13b14e` | Increments R13, compares it with private field2, then branches back to row setup. |

**[verified offline under both explicit order assumptions]** A separate bounded replay starts at original initializer `0x61525a`, using external tag10 **low-half-first**, synthetic descriptor/stack and varying argument registers. It executes every reached original instruction and stops after assigning private fields0..2. It skips no callbacks or memory clearing. The initializer assigns **field0 =16 and field2 =2**, independently of incoming R12 values8/16/32 and a distinct R8 sentinel. Source chain: the immediate16 at `0x615279`, staged at `0x61527e`, passes through `0x600c78` to global `0x2122d0`; the immediate2 at `0x6152a6` reaches global `0x2122d2`. The constructor loads those globals at `0x6010ec`/`0x601109` and assigns the fields at `0x6010ef`/`0x601113`. The replay reaches those assignments after900 encoded instructions. This is prefix validation, not complete constructor/lifecycle qualification.

Thus the selected process's **conditional word-buffer convention is two contiguous 16-word rows** for each input/output buffer. This supersedes any inference that the first synthetic2-word inner loop alone established interleaving. A preliminary DM12-offset interpretation was rejected by varying that field: the actual address product uses row index R13 and field0. Reports retain `native_stereo_abi_verified=false`; neither row identity (L/R) nor float interpretation has been measured on the unit. The consumer proof below establishes float arithmetic use conditionally offline.

**[unresolved loader ordering]** The shipped boot kernel dispatches tag3 at `0x8c01f/20` into handler `0x8c048..0x8c058`. It reads packed words through helper `0x8c033` into normal DM `0x92003`, loads short aliases `0x124006` and `0x124007` into R6/R7, and stores them in that order through I0 with M6=1. This establishes store order but not the complete link-transfer/cross-width half-selection mapping. High-half-first yields the coherent decoded path and constructor above; a physical byte-order proof must still reconcile that interpretation with the boot/link transport and ADSP-21469 aliasing. The helper does not silently choose the more plausible order.

**[verified offline under explicit parcel order; invariant across two immediate-extension hypotheses]** `inspect_input_word_float_use` follows the first actual input word through original encoded instructions: incoming `I1[0]` is read at `0x13ae6a`, copied to staging at `0x13ae6d`, loaded into R4 by a compact dual-load at `0x1828a9`, then used as F4 in **F12 = F2 × F4** at `0x1828ab`. Execution stops immediately after that multiplication, after207 instructions. The previously unsupported negative immediate at `0x1828a0` is evaluated in two separate explicit sign/zero-extension experiments; both produce identical input provenance, coefficient and float result. The default decoder still stops on that unresolved form. Four varied input/coefficient pairs, including negative and small values, match float32 results exactly, and an independent read spy rejects any dereference of sample/coefficient bit patterns as addresses. The compact read-only dual-load is separately checked against our assembler. This establishes the copied word's float arithmetic use under selected code order without selecting unknown immediate semantics or emulating the remaining DSP body. Physical INIT16 order, channel identity and native context remain unproven.

## Delivered diagnostic, not a production adapter

**[verified offline]** [microlooper_adapter.asm](../../../src/sharc/microlooper_adapter.asm) is a native-context sampler with a documented caller contract, not an interleaved/planar converter. Its caller must provide at least 200 private DM words through `I0`. It writes a 16-word snapshot at offsets 160..175 and uses offsets176..179 for ASTAT/STKY,180 for source sequence and192..199 as private register-save/SIMD padding. Publisher scratch181..189 is reserved for the telemetry variant. It preserves modified registers, MODE1, ASTATX/Y and STKYX/Y; all words0..159 are untouched. Snapshot fields are magic, call count, I0/I1/I2/I3/I8, B1/L1/B2/L2, MODE1, candidate instance pointer, candidate SDRAM start/end, and an extent plausibility flag. No global/singleton storage is used.

**[verified offline]** The sampler never reads from input/output sample pointers. Before following `DM(2,I3)`, it requires the complete three-word call record inside one actual normal-word SRAM window: `[0x92000,0x9e000)`, `[0xb2000,0xbe000)`, `[0xc0000,0xc8000)` or `[0xe0000,0xe8000)`. It requires the complete eight-word candidate descriptor inside one of those windows before reading words6/7. The unsigned predicate clears address bit17 to fold banks1/3 onto0/2, then checks normalized intervals with the appropriate extent; original pointers are retained for reads. ROM, reserved gaps and records crossing a bank end are rejected before dereference. Tests exercise every accepted bank edge and forbidden reads in ROM/gaps/crossing cases, while preserving registers and status. SDRAM is plausible only when its extent is external normal-word space and at least48,000 words. These bounds are not allocator-ownership proof. The sampler does not initialize or write SDRAM or pass audio through.

**[verified offline]** [tests](../../../tests/test_microlooper_adapter.py) run the actual encoded sampler in `ssim`, check raw register snapshots, register/MODE1/ASTAT/STKY preservation with SIMD enabled, state guards, unchanged parameter words, invalid descriptor paths, decoder validation and stock graph/registry inspection. The state allocation includes one padding word because a MODE1 store made before disabling SIMD can touch its paired neighbor. The diagnostic does not select a physical stereo memory layout and all decoded reports retain `native_stereo_abi_verified=false`.

**[verified offline / conditional allocation]** `MICROLOOPER_ADAPTER_ACOUSTIC_DIAGNOSTIC` calls the sampler and tail-jumps to original process `0x8e9e3`. Tests execute the wrapped and original real ISA bridges and compare all R/S/I/M/B/L registers, MODE1, ASTAT/STKY at original entry and the VISA handoff, plus balanced PC/loop stacks. This entry requires 200 actual private DM words and original AcousticSim init/control/parameters/SDRAM metadata. Growing registry metadata alone has not been established to grow the native allocation; no build may use this entry until allocation is proven. `assemble_diagnostic(pm_base, sidecar_dm)` generates an absolute-DM version and returns `MICROLOOPER_ADAPTER_GLOBAL_CONTEXT` plus `MICROLOOPER_ADAPTER_GLOBAL_ACOUSTIC_DIAGNOSTIC`. It leaves native I0 and all native instance words untouched; the same snapshot records the original I0. Root integration must reserve the sidecar and PM in verified free memory and preserve original graph/init/control metadata. Both forms currently assemble to121 instructions (122 with loader padding,183 normal words) and200 DM words; wrapper entry is PMbase+119. The global assembler validates even alignment and containment in actual ADSP-21469 SRAM ranges, but cannot establish that a supplied address is free. Standalone tests preserve all R/S/I/M/B/L, MODE1, ASTAT/STKY, native DM contents and sidecar guards; the real stock bridge equivalence test covers both forms. A shared diagnostic log records the last invocation only; it neither implements nor imposes a production instance-count rule. Neither test executes the original VISA body or proves audible operation.

## Remaining proof and adapter decision

**[hypothesis: required experiment]** Instrument a real invocation of the selected stereo host, preserving its processing function and recording the snapshot through an already-validated telemetry path. Feed distinct known L-only and R-only signals. Establish whether I1/I2 and the call-list/instance records describe contiguous planar regions, interleaved samples or pointer lists, and whether circular lengths/modifiers matter. Read-only lane checks must precede writes. Verify same-buffer and separate-buffer cases, descriptor extents on create/recreate, and state changes under bypass. Only then implement and test the minimal conversion/adapter into the micro-looper core's interleaved 16-frame interface.

If offline dataflow stops on a runtime value, the narrow replay fixture needed is one unmodified invocation at `0x8e9e3`: all R/I/M/B/L registers, MODE1, PC stack/loop context;16 normal words at `I3`;16 at `DM(2,I3)`;32 at each `I1` and `I2`; and16 at each in-range internal-RAM pointer found in those records. Capture it first for known L-only, then R-only input. Include both same-buffer and distinct-buffer routing if the host permits it. This goes beyond the current16-word sampler, which cannot identify sample lane contents or reconstruct the complete C context. No such runtime fixture was obtained in this session.

In particular, read private fields0/2 through **word0 of the validated instance descriptor**, rather than assuming incoming I0 is that private base. Those values plus known L/R input words directly test the conditional16×2 result. Sidecar auxiliary words190/191 remain free for dimensions in a later diagnostic revision; publisher saves now occupy181–189; the current16-word register snapshot does not include them. The current transport exports the16-word register snapshot only.

**[hypothesis: release gate]** Do not register the core against a guessed native stereo interface, and do not equate a simulator pass under explicit synthetic pointers with on-device ABI verification. Per-instance SDRAM lookup at words 6/7 has existing NAM evidence, but stereo ownership and lifecycle must be confirmed in the selected host. The audio port may proceed independently against its explicit caller interface while this diagnostic gate remains open.

## Development planar conversion bridge

**[verified offline under an explicit caller contract]** The [bridge](../../../src/sharc/microlooper_bridge.asm) converts two contiguous 16-word float planes into the core's private interleaved buffer, calls the actual audio core, and converts back. It validates complete call/instance descriptors against the four SRAM windows before following pointers, delegates SDRAM extent validation to the core and preserves registers, DAG metadata, MODE1, ASTAT and STKY. There is no shared capture state. The caller must initialize/reset the core marker on each new graph; this is not a native init callback or a lifetime detector.

**[verified offline]** The bridge has 101 instructions /102 padded,624 loader bytes and 199 total private DM words. Its 100 tests include bit-exact encoded-core comparison across all three modes, controls, capture/listen and overdub; planar in-place/separate routing; two independent instances; relocated calls; status restoration with forced callee clobber; and SRAM bank/ROM/gap/extent checks that trap forbidden reads. See [test_microlooper_bridge.py](../../../tests/test_microlooper_bridge.py). The simulator's explicit planar-float caller is still a contract, not a native dispatcher certification.

**[verified offline; hardware acceptance pending]** The explicit development builder now links the bridge with custom init/control callbacks and installed M4 lifecycle routing. The resource tool's `--bridge` mode measures core/bridge only; the complete builder measures all callbacks too, coalesces adjacent PM records and leaves 12 Entry 2 bytes in the full NAM1/GR/metronome profile. Native private allocation and I0 dataflow are executed in bounded stock-code tests. Physical loader ordering, native L/R identity, complete boot and scheduling remain device checks. Default release/browser builds remain disabled for this feature; see the [integration record](microlooper-integration.md).
